# FONT-1 - Step 0 (REPORT ONLY - no code, data or config changed; testing_agent not used)

Context: iPhone 16 Pro, iOS Larger Text at the largest Larger Accessibility size. MOBILE-FIX-1 earlier fixed Android "Display size Large" + 3-button nav; iOS accessibility sizes scale fonts much higher (up to ~3.1x) and expose fixed heights and single-line text that Android's smaller bump did not.

## A. How font scaling is handled today
- No global default. The app does NOT set `allowFontScaling` or a global `maxFontSizeMultiplier` anywhere (no Text defaultProps). So every `<Text>` and `<TextInput>` scales with the iOS system size unless a component opts out locally.
- MOBILE-FIX-1 added LOCAL caps/auto-fit on a handful of spots only: bottom tab labels (`app/(tabs)/_layout.tsx`: `adjustsFontSizeToFit`, `minimumFontScale 0.7`, `maxFontSizeMultiplier 1.15`), the shared `Picker` trigger (`ui.tsx`: `adjustsFontSizeToFit` + `maxFontSizeMultiplier 1.2`), the Hub month header and date badges, and the directory header title. It did NOT introduce an app-wide policy, so most screens still scale uncapped and most titles/names are `numberOfLines={1}`.
- Shared components in `src/components/ui.tsx`: `Button` (numberOfLines 1, cap 1.3), `ButtonRow`, `Badge` (no cap, no wrap), `Chip` (no cap, no wrap), `Avatar` (fixed size, NO `flexShrink:0`), `SegmentedControl` (numberOfLines 1, no cap), `Picker` (capped), `FilterButton`. Shared `Screen` header in `src/components/Screen.tsx`.

## B. The nine problems - root cause, shared scope, fix
1. Headers cut in half. Two duplicated patterns: (i) shared `Screen.tsx` header `styles.header { height: 52 }` + title `numberOfLines={1}` with NO font cap (used by ProDetail, NotificationsScreen, HubDetail, EventDetail, org/[id], profile/index, messages/[id], following, reviews, my-plan, etc.); (ii) per-tab CUSTOM headers that copy the same `header: { height: 52 }` + `hTitle: { fontSize: 20 }` + `numberOfLines={1}` (feed, events, messages, directory, my-listing, my-events). A fixed 52px row cannot hold a 3x title, so it clips. Fix: `minHeight` not `height`, cap the title at ~1.3x (`maxFontSizeMultiplier`), allow 1-2 lines; do it once by extracting ONE shared header and routing the tab screens through it.
2. Tab labels - descenders clipped (Messaqes, Oras). `_layout.tsx` label has a FIXED `lineHeight: 14` at fontSize 11, and the label sits in a tight slot (`TAB_BASE 52`, `paddingTop 6`). Even with the 1.15 cap the glyph box is taller than 14, so g/q/s tails are cut at the bottom. Android looked fine because its bump was smaller. Fix: drop the fixed `lineHeight` (or raise it and add a few px of label headroom / raise TAB_BASE slightly); keep the 1.15 cap.
3. Truncated with ellipsis (event titles+dates, Following banner, Hub titles, Messages sender names, review author names, review count, org name). Everywhere `numberOfLines={1}` on names/titles/counts: events `when`/`meta` line 1, messages `name` line 1 (sender shows one letter + ...), directory `title`/`meta`, Hub card `author` line 1, review author + count, org name. Fix: let names/titles/counts WRAP to 2-3 lines (`numberOfLines={2|3}` or none) and give the parent `flexShrink:1` so the text takes the width instead of truncating.
4. Mid-word breaks (Newsletter row, Appearance Light/System/Dark, Hub location line). Long words forced into a too-narrow fixed container wrap at the character. Appearance = `SegmentedControl` (3 equal segments, numberOfLines 1, no cap) - at 3x the label can't fit a segment. Location line / Newsletter row sit in rows without room to grow. Fix: cap these control labels (they are chrome, ~1.2x), give rows `minHeight` and allow the value to move to its own line; avoid fixed-width wrappers so words break on spaces not mid-word.
5. Chips/badges overlap or distort (pro profile category chip over the one below; Founding Partner badge). `Badge`/`Chip` use fixed vertical padding, no cap, no wrap, and chip rows that don't `flexWrap` or that rely on fixed heights collide when the text grows. Fix: chip/badge rows `flexWrap: "wrap"` with row `gap`, chips/badges use `minHeight` + `alignSelf:flex-start`, cap their text (~1.2x, they are labels).
6. Avatars squeezed to slivers (Hub cards, review cards, Profile). Shared `Avatar` (`ui.tsx`) draws a fixed `width/height=size` but has NO `flexShrink: 0`; in a flex row next to long scaled text the layout engine shrinks the avatar's width. Fix: add `flexShrink: 0` (and give the neighbouring text `flex:1`). One change in the shared Avatar fixes every card.
7. Hub floating + covers the Found crew badge / card content. `feed/index.tsx` `styles.fab` is `position:absolute; right:20; bottom:24`, and the list's `contentContainerStyle` has no bottom padding reserving space for it. Fix: add bottom padding (~fab height + margin) to the list content so the last card clears the FAB (and/or lift the FAB above the tab bar inset).
8. Text inputs clip their text (handle, first name, multiline placeholder). `TextInput`s use a fixed `height` (e.g. the shared input is `height: 50`) so scaled text is clipped; multiline placeholders need room to grow. Fix: `minHeight` instead of `height`, `textAlignVertical:"top"` for multiline, and a sensible input font cap.
9. Profile top runs to the screen edges (name, Log out, Switch account). The Profile hero row in `app/(tabs)/profile/index.tsx` sits outside the padded body (full-bleed) and its inner row lacks horizontal padding, so at large text the items touch both edges. Fix: add consistent horizontal padding to the hero row and let the name wrap.

## C. Proposed approach (I agree with your four points)
1. Chrome (header titles, tab labels, chips, badges, buttons, segmented control, date badges): cap at a MODEST multiplier (~1.2-1.3) and auto-fit where needed, so structural furniture stays intact.
2. Body/content text (names, titles, dates, counts, bios, locations, messages): allow FULL scaling but WRAP to 2-3 lines instead of truncating; remove `numberOfLines={1}` on these or raise it, and give parents `flexShrink:1`.
3. Replace fixed `height` with `minHeight` on headers, rows, inputs, chips, badges; give `Avatar` a non-shrinking fixed size (`flexShrink:0`); avoid fixed-width text wrappers so words break on spaces, not mid-word.
4. ONE shared approach, not per-screen patches: (a) set app-wide Text/TextInput defaults (a single root `maxFontSizeMultiplier` policy, e.g. via a small shared `AppText`/`defaultProps` or a theme helper) so new screens inherit it; (b) extract a single shared Header and route the 6 custom tab headers + `Screen.tsx` through it; (c) fix the shared `Avatar`, `Chip`, `Badge`, `SegmentedControl`, and the shared input style once. I do NOT disagree. The only nuance: an app-wide "cap everything" would also cap body text (bad for accessibility), so the policy must be two-tier - a modest cap for chrome components, and wrap-not-truncate (higher or no cap) for content text. That matches your points 1 and 2.
